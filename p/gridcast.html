Tomorrow's load curve — and the peak you actually care about.

A peak-aware electricity-demand forecaster presented as a grid control room: drag the weather dial and watch the load curve and a peak-risk meter respond live — judged on catching peaks, not just average error.

Open the live demo → View code

Problem

Grid operators care about the peak — when and how high demand spikes. Naive baselines just repeat yesterday and badly miss weather-driven peaks; raw MAPE hides that.

Approach

Stream a multi-million-row load series chunked to columnar Parquet (queried out-of-core via DuckDB), train weather-aware LightGBM quantile models, and score them on peak-capture metrics, not just average error.

Result

A control room with a real /whatif endpoint and an honest prediction band — where the model lands the peak within ~4 hours and the baselines don't.

Insights

What it shows

Scale is a discipline, not a dataset size. The 2.1M-row ingest peaks at ~41 MB because memory scales with the streaming chunk, not the row count — a test asserts 4× the rows costs nowhere near 4× the memory.

Average error flatters the wrong thing. The naive baselines look fine on MAPE yet miss weather-driven peaks by ~10 hours; scoring on peak recall + timing is what makes the model's win real.

No naked forecasts. Every prediction renders with a calibrated p10–p90 interval (coverage ≈ 0.75) — a single line is forbidden in both the API and the UI.

Interactivity is wired to the model. The what-if weather dial hits a real /whatif endpoint backed by a fast surrogate, not a faked animation.
