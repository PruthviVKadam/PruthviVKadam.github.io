A/B Testing · Experimentation · Live

Peeking inflates false positives 5% → 25%

An interactive lab for designing and reading A/B tests the way they should be read — power analysis, the early-stopping trap, and CUPED variance reduction, all driveable live.

Open the live demo → View code

Problem

Designing and reading A/B tests correctly — power, peeking, variance reduction — is easy to get wrong, and the mistakes quietly ship bad decisions.

Approach

A Streamlit app with three tools: a sample-size designer, a two-proportion analyzer (real Cookie Cats data / CSV / counts), and a Monte-Carlo simulator for peeking + CUPED.

Result

Theory you can drive: watch the false-positive rate balloon as you peek, and the CI tighten as CUPED removes variance — all from pure, unit-tested statistics.

Insights

What it shows

Peeking destroys false-positive control. Under the null, checking once gives ≈5% false wins; stopping the moment p<α pushes that toward 25% — the result is a fluke, not a finding.

The fix is procedural, not statistical. Fix the sample size in advance (the designer) or use a sequential correction — the data isn't the problem, the stopping rule is.

CUPED buys power for free. Adjusting on a pre-experiment covariate cuts variance by ρ² without biasing the effect — narrower CIs at the same sample size.
